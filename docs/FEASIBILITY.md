# 可行性调研与旧项目诊断

调研起始 2026-09-22，实施持续到 2026-09-23。必须区分官方历史介绍、用户本机历史证据和本次实机检查；不能把旧活动当作当前永久规则。

## 入口证据

1. 永劫无间官方网站 2024-06-06 的[官方介绍](https://www.yjwujian.cn/news/official/20230704/33961_1096666.html)明确给出公众号“福利中心 → 暗潮商店”入口。它支持历史入口来源，不证明当前所有签到规则。
2. 上级旧项目 `artifacts/binding/20260916-151343/01-unbound.png` 的实际截图显示福利中心的“端游 / 手游”、“你尚未绑定游戏账号 / 立即绑定”。文件名不能代表截图的真实绑定状态，必须读图。
3. 旧项目 2026-09-16、2026-09-20 的截图显示签到日历以及金钥匙、阅读、名片、海报、每日登录游戏的独立任务按钮。
4. 本次 2026-09-22 23:25 已启动本机 `D:\Weixin\Weixin.exe`，通过保存的登录进入微信，实际进入小程序福利中心。看到 9.22 日历格为勾选，金钥匙“去完成”，其他多项“已完成”。这与用户说明当天多数任务自行完成一致。
5. 桌面上名为“永劫无间.lnk”的文件实际指向游戏工具 `LootHoarder.exe`，不是微信小程序。因此不能仅按同名快捷方式猜测入口。

## 前置条件和可自动范围

Windows 必须有可交互的已解锁桌面。微信已安装，登录状态有效；首次扫码、手机确认、授权、角色绑定不能由程序凭空满足。当前存在保存登录时可自动点击“进入微信”。小程序须至少正常访问过一次，或配置微信生成的小程序快捷方式。

可在已知界面完成：找到唯一的小程序窗口；从发现/最近使用打开；关闭已识别的提示/活动弹窗；选择游戏版本；读取日历/任务行状态；执行普通签到、阅读、内容生成及答题；检查执行后状态。

必须停下：二维码登录需要手机确认、验证码/风控、账号限制、未绑定或角色不符；活动已结束；页面改版使按钮含义不确定；金钥匙来源日期无法确认；登录游戏任务前置条件未满足。程序提示明确的失败原因，不要求用户每天对正常成功结果点确认。

名片和海报流程不发送消息。若服务端规则要求真实分享给他人，工具无法在没有收件人授权时自动满足；只会记录未完成。奖励数值可能变化，不能用固定积分增量证明成功。

## 旧项目为何不能原样沿用

- 2026-09-21 最后一次记录失败于未识别最近使用小程序的搜索结果。
- 2026-09-20 曾失败于从小程序页返回聊天列表后未识别搜索框。
- 签到依据当前格亮度小于 90 判断“已签到”，可能把暗色未签格误判成功。
- 操作后强制要求积分增加恰好 1，绑定固定奖励。
- 整轮流程包含多类任务，任何页面变化可能导致整体失败；无独立任务状态 UI 与可靠日程持久化。
- 旧项目 17 项单元测试通过并不能证明当前导航成功，本次新版本必须再做实机测试。

新项目保留可复用的底层窗口检查和 OCR，使用当日日期与图标模板联合识别，按任务验证反馈；用 SQLite 保存计划、任务和执行日志。自动化仍是界面驱动，不能承诺任意未来页面均可运行。具体本次运行结果另见 `VALIDATION.md`。

## 本次金钥匙规则核实
